## Selected work

<div align="center"><img src="./assets/project-ecosystem.svg" width="96%" alt="Animated map of Kaustubh’s engineering work"/></div>

### 01 · GitGlobe
**A 3D map of the open-source universe.**

GitGlobe places **198,731 repositories** on an interactive globe according to what they do rather than what they are called. It combines semantic embeddings, spherical UMAP, WebGL rendering, search, repository ranking and a popularity-blind quality model.

`React` `TypeScript` `Three.js` `FastAPI` `Qdrant` `PostgreSQL` `ML`

**[Explore GitGlobe →](https://github.com/kaustubhdua/GitGlobe)**

### 02 · Nirdhoom
**Field → service → evidence → residue → buyer.**

A field-first crop-residue coordination platform designed around the operational chain rather than another dashboard. The system combines field workflows, booking, dispatch, operator evidence, verification, residue pooling and an OR-Tools dispatch foundation.

`React` `Vite` `Supabase` `PostgreSQL` `Leaflet` `OR-Tools` `PWA`

**[Explore Nirdhoom →](https://github.com/kaustubhdua/nihdhoom)**

### 03 · Saathi
**Voice-first assistance for real-world workflows.**

A multilingual assistance platform built around source-backed answers, deterministic intent routing, provider adapters, consent, human escalation and measurable readiness gates. The project deliberately separates simulated demos from provider-backed capabilities.

`Next.js` `React` `FastAPI` `Python` `Voice` `AI`

**[Explore Saathi →](https://github.com/kaustubhdua/Saathi)**

### 04 · JYC 128
**An editorial product for JIIT Youth Club.**

The official JYC 128 website combines content architecture, verified public records, media provenance, accessibility, SEO, responsive design, CI, CodeQL and browser QA. It is a good example of treating a website as a maintained product rather than a collection of pages.

`React` `Vite` `Supabase` `CI` `Playwright` `SEO` `Accessibility`

**[Explore JYC 128 →](https://github.com/kaustubhdua/JYC-Website)**

## How I build

```text
PROBLEM
   ↓
Understand the constraint
   ↓
Design the smallest useful system
   ↓
Build a measurable slice
   ↓
Test the failure modes
   ↓
Document what is actually true
   ↓
Ship → observe → refine
```

I care about **clarity over cleverness, evidence over assumptions and useful software over feature count**.
